# Mission Groups（local.mission-groups）2.0

主機決定各星球會建立哪一個原版任務組（行動）。客機不用裝 mod，8 人大廳也能用。只支援遊戲構建 25480438。

## 原理：什麼能同步、什麼不能

HellForge 後端記錄了遊戲建立任務組時送出的內容（`<session>\backend\mission-bodies\*-Operation_Create.json`）：

```
{"operationSettingsId": 2350081063, "seed": 548846115, "planetIndex": 269, "race": 2, "difficulty": 11,
 "missions": [{"index": 0}, {"index": 1}, {"index": 2}]}
```

任務只有序號，沒有任務 ID。每台機器都是拿「任務組 ID（任務組表的某一列）＋種子」，用自己的表推出三個任務，再由任務加種子推出目標、變種和地形。所以：

- **能同步**：主機改用哪一個「原版」任務組。2.0 把一整列原版任務組（含 ID）蓋到遊戲本來會選的那一列，主機建立出來的就是那個原版任務組，種子照遊戲自己的。客機用自己沒改過的表，推出一模一樣的任務。
- **不能同步**：自己拼任務清單。1.0 是在主機改某一列的任務清單，客機的表沒改，同一個任務組 ID 和種子會推出別的任務，所以 2.0 拿掉了這個功能。設定檔裡要是還寫著任務清單，mod 會拒絕整份設定並寫進日誌。
- 任務列與目標表一個位元組都不改。這台機器當客機時不寫任何東西，之前改過的也會先還原。
- manifest 是 `"coop": "per-player"`，不進 modlist code，客機加入時不會被要求下載。不碰玩家槽位，8 人沒問題。

## 使用

1. 先玩一次：session 日誌資料夾會出現 `mission-groups-catalog.txt`，列出 25 個任務組（列號、ID、陣營、含哪些任務）和全部任務列。
2. 建立一次任務組：mod 日誌會寫 `operation created: planet 269, … vanilla row 1 …`，就知道那顆星球用的是哪一列。
3. 編輯 mod 資料夾裡的 `mission-groups.txt`，例如：
   ```
   [operation 1]
   use 6
   ```
   存檔後回到船上約 1 秒生效。
4. 放棄目前的任務組，或換星球、換難度讓遊戲重新建立。日誌那一行結尾會多一句 `from mission-groups.txt`。

想讓任何星球都能選，用 HellForge 的 `--war open` 啟動。

## 實測（兩台機器）

主機套用設定、建立任務組，然後讓客機加入：

1. 不裝 mod 的客機：看戰略桌上的三個任務和任務中的目標，是否和主機一樣。
2. 裝了 mod 的客機：當客機時只記錄、不改動。兩邊 `mod-local.mission-groups.log` 的 `mission start` 段應該寫出同一個任務組與任務列，前 0x100 位元組也一致。

## 限制

- 單位是「任務組表的一列」，不是單顆星球：同一列可能有好幾顆星球在用。要找出「星球選哪一列」的程式位置，需要另外逆向。
- 換掉之後，被蓋掉的那一列原本的 ID 在主機上就不存在了，日誌會寫 `note: … is not offered`。換之前請先放棄用那個 ID 建立的任務組。
- `cross_faction = 1` 可以換成別陣營的任務組，但敵人和星球可能不搭，沒有測過。

## 和 HD2 CampaignLab 的關係

CampaignLab 在 war Status 裡加星球效果 ID，例如寂域任務組 #1410／#1411／#1412、掠食變種 1243+1245。它靠的是本機 HTTPS 代理：改 hosts、裝臨時根憑證，而且只改跑代理的那一台。

- **任務組**：效果 ID 最後也會變成某個 `operationSettingsId`。如果那個任務組在這 25 列裡，用本 mod 的 `use` 直接指定就好，不需要代理，客機也同步。
- **敵人變種**：屬於每台機器各自的 war Status。只有主機有的話，客機不知道要載入變種的資源，所以沒辦法在客機免 mod 的前提下同步，沒有移植。
- 它的變種目錄是 1.007.200（構建 25988413）的，比 HellForge 的 25480438 新，部分 ID 在這個構建可能不存在。
