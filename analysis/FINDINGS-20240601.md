## 格式相容性（同名資源、兩版都有）

每型抽樣 40 個比較內容：

| 類型 | 結論 |
|---|---|
| physics、animation、state_machine、bones、texture、prefab、entity | 大多逐位元組相同，可直接沿用 |
| unit | 全部不同。約 1/5 只差 +0x2C 一個 u32（0x00000001 → 0x00A4CD36），其餘多長了 8–248 位元組：結構改過 |
| level | 全部不同，但 68% 大小相同；差在檔頭 u32（0x00A54D49 → 0x014A1A7F）、和 unit 同一個 0x00A4CD36 欄位，以及少數幾處 |

| particles | 版本 0x6B → 0x73，全部大小不同 |
| wwise_bank | 全部不同（推測 Wwise 版本升級） |

所以舊資源不能原樣放進現行遊戲：level、unit、material、particles、音效庫都要轉換。

## 實機結果：舊資源被版本檢查擋下

zz.compat-level（只換撤離點地形）讓遊戲開機就報 0x44415441（"DATA"）。引擎日誌：
`[Unit] Incorrect version found when loading Unit Resource '#ID[46cab355bd8d4d37]' (expected: 10800438, actual: 1)`。
補丁在開機載入的 9ba626afa44a3aa3 資源包裡，所以開機就檢查。舊資源一定要轉換。

模型版本時間線（unit +0x2C）：2024-06 = 1，2024-12 = 1（鑽機、super_syringe、0e4e… 抽樣），現行 = 10800438。
HD2SDK 能讀的中間版本 10800437 出現在 2024-12 之後；而 5 個印模包在 2024-12-17（以及 2025-04-02、2025-09-08）
的版本都已不在。所以任何還帶著這些地形的版本，模型都是版本 1，往前找無助於轉換。

## 模型 版本 1 → 10800438 的差異（unit_diff.py、unit_section_diff.py）

以兩版都有、GPU 資料相同的模型比對（孢子燈、鑽機、0e4e…）：
- 標頭 +0x2C 版本：1 → 10800438。
- LOD 群組清單：多 16 位元組（每個群組前插入一個 0xFFFFFFFF，清單尾多 12 位元組），之後所有區段位移 +16，標頭裡的區段位移跟著加。
- 頂點串流資訊：大小不變，頂點格式代碼凡 > 16 的加 4（0x1A→0x1E、0x1D→0x21），與 HD2SDK 對 10800437 的處理相同。
- 結尾區段：8 → 16 位元組（補 8 個 0）。
- 骨架、變換、網格、材質區段：多半逐位元組相同，只是位移。
- 燈光參數、LOD 距離數值：美術重調過的內容差異，沿用舊值即可。
