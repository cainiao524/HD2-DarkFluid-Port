## 3. 目標的執行邏輯（已確認，見 analysis/BEHAVIOR-LOGIC.md）

- **行為 id：** 388 是部署（backpack），389 是 bridge，390 是投放點（thumper），552 是鑽頭投放，435 是背包。
- **目標狀態：** 存在 `[ObjectiveManager+0x60] + i*0x1078 + 0x1018`。
  - 0 啟用、1 未啟用、2 或 3 結束。
  - `game.dll 0x4D7FC0(_, id)` 會把目標啟用。
- **原版流程：**
  1. 容器接管部署目標時，引擎發出 `0x8ED59ACA`。
  2. 部署收到後推進一步，並廣播 `0x0F197F6D`。
  3. 3 個投放點看自己單位的腳本資料 `0xF52812AA`（id_01～03），收到廣播後啟用。
  4. 鑽頭開始時會廣播事件，暫時關掉另外兩個投放點。
  5. 每個投放點完成時發 `0x8EFF1CFE`，部署進度 +1；進度到 3.0 時部署完成。
- **移植版的補位：** 移植版收不到 `0x8ED59ACA`，所以 mod 會補兩件事：
  - 部署目標開局沒有啟用時，5 秒後由 mod 啟用。
  - 容器生成 5 秒後：
    - 投放點沒被啟用的，由 mod 啟用。
    - 部署如果沒有推進，mod 用 `0x5D7CE0` 補推進一步。

## 4. 降落崩潰（4 級以上，1.0.13 修正）

- **找原因的方法：** 用 `tools/mdstack.py` 解析 HellForge 的崩潰傾印，再加上 exe 映像裡的 EngineApi 結構（`exe+0x27C8D80`）。
- **崩潰點：** `game.dll 0x5D1546`，位在目標設定 `0x5D0DE0` 裡。
  - 目標設定會對目標列出的關卡物件，讀腳本資料（鍵 `0x2AA21BB6`）。
  - 讀取函式是 `[[[EngineApi+0xB8]]]+0x10`，也就是 `helldivers2.exe+0x32F6A0`。
- **原因：** 4 級以上，關卡的難度層沒有生成部分物件，代號因此無效。`exe+0x9D8C0` 回傳 NULL，`0x32F6A0` 沒有檢查就讀取。
- **修正：** mod 掛鉤 `exe+0x32F6A0`。代號查不到物件時，回傳 16 個 0，呼叫端原本就會跳過這種結果。
- **待查：** 這些物件在舊版是不是正常存在。

## 5. 紫色地表（v1.0 修正）

- **地形貼片單位：** `+0x1FC` 是標記 `0x120ad0a0030576f2`。`+0x21C` 指向 R16 高度圖，`+0x404` 指向 R32 遮罩。
- **遮罩內容：** 每格最高 6 位元是地表層編號，1.001.104 之後重新編號過：

  | 1.001.104 | 現行 |
  |---|---|
  | 4 | 3 |
  | 8 | 22 |
  | 9 | 23 |
  | 10 | 24 |

  這張表是用兩版共有的貼片 `d2292afe2483e88c` 對出來的，各編號的格數完全相同。
- **原因：** 暗流體的遮罩全部用 8～10，現行版沒有 8 號層，所以畫成洋紅色。8 號層就是蟲族菌毯。
- **修正：** `build_port_resources.py` 在打包時重新編號（`patch_masks` / `remap_mask`）。
